# API Хаотики v1

Первая версия для собственных скриптов, ботов и автоматизаций. Базовый URL после
развёртывания: `https://chaotika.ru/api/public/v1`. Интерактивная документация:
`https://chaotika.ru/api/docs/#/integrations`, спецификация: `/api/openapi.json`.

Swagger и его JSON/YAML содержат только девять методов public API: задачи и покупки.
Они одинаковы для всех посетителей, включая владельца приложения. Управление
аккаунтом, ключами, участниками и внутренние методы приложения в этот каталог
не входят. Ключ создаётся и отзывается в настройках Хаотики.

## Подключение

1. Войдите в Хаотику и выберите нужное пространство.
2. Откройте **Ещё → Настройки → API и интеграции**.
3. Укажите название интеграции, срок действия и разрешения.
4. Скопируйте ключ сразу: повторно увидеть секрет нельзя.
5. Сохраните его в секретах автоматизации или переменной окружения
   `HAOTIKA_API_KEY`. Не добавляйте секрет в репозиторий, URL или клиентский JavaScript.

Каждый запрос передаёт `Authorization: Bearer <ключ>` по HTTPS. Заголовки
`x-actor-user-id` и `x-workspace-id` для интеграций не нужны: пользователь и
пространство уже определены ключом. Подмена пространства запрещена.

| Разрешение       | Доступ                                     |
| ---------------- | ------------------------------------------ |
| `tasks:read`     | Список, поиск, получение задачи            |
| `tasks:write`    | Создание, изменение полей и статуса задачи |
| `shopping:read`  | Список, поиск, получение покупки           |
| `shopping:write` | Добавление, изменение и отметка покупки    |

Чтение и изменение выдаются отдельно. Ключ ограничен текущими правами своего
владельца в пространстве. Он не даёт доступ к настройкам аккаунта, другим ключам,
заметкам, заботе, уборке или административным методам. Для другой интеграции
создавайте отдельный ключ. Максимум — 20 действующих ключей, срок — 1–365 дней.
Отзыв, истечение срока или потеря доступа к пространству блокируют следующие запросы.

## Задачи

| Метод | Путь                 | Действие                  |
| ----- | -------------------- | ------------------------- |
| GET   | `/tasks`             | Страница задач            |
| GET   | `/tasks/{id}`        | Одна задача               |
| POST  | `/tasks`             | Создание                  |
| PATCH | `/tasks/{id}`        | Частичное изменение полей |
| PATCH | `/tasks/{id}/status` | Смена статуса             |

Создание требует только `title`. Дополнительные поля: `id` (UUIDv7), `note`,
`project`, `plannedDate`, `dueDate`, `importance` (`important`, `not_important`),
`necessity` (`required`, `desired`, `optional`), `resource` (целое от −5 до 5).

Даты имеют формат `YYYY-MM-DD`. `plannedDate` — дата плана, `dueDate` — дедлайн.
Создание без дат оставляет задачу гибкой. В PATCH значение `null` очищает дату,
отсутствующее поле сохраняет текущее значение. Очистка `plannedDate` также снимает
время и напоминания, сохраняя правило повторения. Изменение остальных полей
сохраняет время и часовой пояс существующей задачи.

Повторы используют настройки часового пояса планера; в режиме «Устройство» API
берёт последний сохранённый пояс устройства, а при его отсутствии — UTC.
У задач с фиксированным часовым поясом сохраняется пояс самой задачи.

Изменение задачи и статуса требует `expectedVersion` из последнего ответа API.
При конфликте сервер возвращает 409; перечитайте задачу и согласуйте изменения.
Статусы: `todo`, `in_progress`, `ready_for_review`, `done`, `archived`.
Действуют правила обычного планера, включая роли участников и повторяющиеся задачи.

Список поддерживает `search`, `status`, `plannedDate`, `limit` (1–100, по умолчанию
50), `offset` (с 0). Ответ: `{items, limit, offset, nextOffset, hasMore}`.
Следующая страница запрашивается с `offset=nextOffset`, пока `hasMore=true`.

```bash
# Ключ заранее задан в окружении. Команда не записывает его в историю shell.
curl --fail-with-body 'https://chaotika.ru/api/public/v1/tasks?limit=10' \
  -H "Authorization: Bearer $HAOTIKA_API_KEY"

curl --fail-with-body 'https://chaotika.ru/api/public/v1/tasks' \
  -H "Authorization: Bearer $HAOTIKA_API_KEY" \
  -H 'Content-Type: application/json' \
  --data '{"title":"Оплатить интернет","note":"Создано моим ботом"}'

# TASK_ID и TASK_VERSION берутся из ответа создания или последнего GET.
curl --fail-with-body -X PATCH \
  "https://chaotika.ru/api/public/v1/tasks/$TASK_ID/status" \
  -H "Authorization: Bearer $HAOTIKA_API_KEY" \
  -H 'Content-Type: application/json' \
  --data "{\"status\":\"done\",\"expectedVersion\":$TASK_VERSION}"
```

## Покупки

| Метод | Путь             | Действие                         |
| ----- | ---------------- | -------------------------------- |
| GET   | `/shopping`      | Страница покупок                 |
| GET   | `/shopping/{id}` | Одна покупка                     |
| POST  | `/shopping`      | Добавление                       |
| PATCH | `/shopping/{id}` | Изменение или отметка выполнения |

Создание требует `text`. Дополнительные поля: `id` (UUIDv7), `priority`
(`low`, `medium`, `high`, `null`), `isFavorite`, `shoppingCategory`
(`groceries`, `household`, `other`, `null`), `productUrl` (HTTP/HTTPS или `null`).

PATCH принимает эти поля кроме `id`, а также `dueDate` (`YYYY-MM-DD` или `null`)
и `status`: `archived` означает «куплено», `new` возвращает покупку в список.
У покупок действует последнее изменение переданных полей; `expectedVersion`
пока не поддерживается. Для выполнения используйте:

```json
{ "status": "archived" }
```

Список поддерживает `search`, `status`, `page` (с 1), `limit` (1–100, по умолчанию
50). Ответ: `{items, total, page, limit}`. Увеличивайте `page`, пока
`page * limit < total`. Обе разновидности страниц не являются снимком: при
одновременных изменениях сопоставляйте записи по `id`.

## Повторные запросы

Для повторяемого POST передайте `id` в формате UUIDv7 и сохраните его до отправки
вместе с телом запроса. При сетевом сбое повторите тот же запрос с тем же `id`:
существующая запись будет возвращена без создания дубля. Идентификатор нельзя
переиспользовать для новой операции или другого содержимого. Это повтор создания,
а не обновление: для изменения используйте PATCH. Удалённые записи не восстанавливаются.

Без `id` повтор POST может создать дубликат. Общий заголовок `Idempotency-Key`
в первой версии не поддерживается. После неопределённого результата PATCH задачи
сначала перечитайте задачу; прежний `expectedVersion` защищает от перезаписи.

Готовые примеры без сторонних зависимостей:

- [JavaScript / Node.js: создание задачи](../examples/public-api/create-task.mjs).
- [Python: добавление покупки](../examples/public-api/add-shopping.py).

Оба примера используют `HAOTIKA_API_KEY`; `HAOTIKA_API_BASE_URL` позволяет
подключиться к локальной тестовой среде. Для сохранённого идентификатора операции
задайте `HAOTIKA_OPERATION_ID`. Генерируемый идентификатор выводится перед запросом.

## n8n

Создайте **HTTP Request**, задайте метод и URL API. В credentials выберите
**Header Auth**, имя `Authorization`, значение `Bearer <ключ>`.
Для POST/PATCH включите **Send Body → JSON**. Для повторов POST сохраняйте `id`
в данных операции. Пример тела создания задачи: `{"title":"Позвонить клиенту"}`.

## Ошибки и лимиты

Форма ошибки: `{"error":{"code":"…","message":"…","details":{…}}}`.

| HTTP | Что делать                                                                   |
| ---- | ---------------------------------------------------------------------------- |
| 400  | Исправить поля запроса; неизвестные поля не принимаются                      |
| 401  | Проверить ключ, срок действия и отзыв                                        |
| 403  | Проверить разрешения и доступ к пространству                                 |
| 404  | Проверить идентификатор записи и пространство                                |
| 409  | Перечитать запись при конфликте версии; проверить повторное использование ID |
| 415  | Передавать JSON с `Content-Type: application/json`                           |
| 429  | Подождать число секунд из `Retry-After`                                      |
| 5xx  | Повторить с задержкой, соблюдая правила повторов выше                        |

Лимиты: 120 запросов в минуту на ключ, 240 на пользователя и 300 на IP.
Это общий бюджет методов, включая чтение. Обычные ограничения ролей пространства
применяются дополнительно к разрешениям ключа.

Опубликованный контракт находится под `/api/public/v1`; несовместимые изменения
должны выпускаться под новой версией. Внутренние методы `/api/v1` не входят в
контракт персональных ключей. Webhooks и OAuth для сторонних REST-приложений —
последующие этапы. Запись через отдельный OAuth MCP-коннектор описана в
[документации ChatGPT](mcp-haotika-chatgpt.md).

## Развёртывание

Перед запуском обновлённого API примените `20261109_000110_api_keys.sql` штатной
командой `npm run db:migrate`. Новые переменные окружения и зависимости не нужны.
Таблица ключей закрыта от прямого доступа роли `authenticated`; управление
выполняется через функции с проверкой владельца, поиск — по SHA-256 случайного
256-битного секрета. Секреты не сохраняются в базе, localStorage или query cache.
В журнал запросов попадают идентификатор ключа, разрешение и шаблон метода.

В production нужен обычный JWT-вход. Режим локальной разработки без авторизации
не позволяет создавать ключи. PostgreSQL-проверки запускаются против отдельной
тестовой БД с применёнными миграциями.
