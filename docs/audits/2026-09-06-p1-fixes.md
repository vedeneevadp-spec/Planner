## Что исправлено

### TD-01. Зависимости и proxy trust

- Fastify обновлён до 5.12.3; lockfile фиксирует fast-uri 3.1.7,
  browserslist 4.28.9, @humanfs/node 0.16.8 и @xmldom/xmldom 0.8.15.
  Новых прямых production-зависимостей и исключений audit нет.
- `API_TRUST_PROXY_ADDRESSES` принимает список IP/CIDR через запятую. По умолчанию
  доверие отключено. Пример для локального Caddy: `127.0.0.1,::1`.
- Новая настройка имеет приоритет над старой, включая явное отключение.
  Legacy `API_TRUST_PROXY_HOPS=1`/`true` означает только loopback;
  остальные положительные значения требуют перехода на адреса/сети.
- README, production example, deploy env allowlist и Playwright согласованы.
  Fastify inject проверяет, что недоверенный peer не подменяет IP/host/protocol,
  а доверенная цепочка останавливается на первом недоверенном адресе.

Основные файлы: `apps/api/src/bootstrap/config.ts`, `build-app.ts`,
`apps/api/package.json`, `package-lock.json`, `scripts/deploy-prod.mjs`.

### TD-02. Преобразование времени и self-care

- Один formatter на зону, максимум 100 зон в кэше. Смещения определяются
  часовыми пробами в том же диапазоне ±18 часов; кандидаты проверяются
  обратным преобразованием. Для разрыва времени используется поиск по минутам
  внутри перехода. Полный перебор 2 161 минуты удалён.
- Сохраняется контракт общего time service: при повторяющемся времени выбирается
  первое UTC-вхождение, при несуществующем — первая допустимая минута после
  разрыва. Проверены обычные DST, 30-минутные переходы Lord Howe,
  дробные смещения Kathmandu/Chatham и пропущенный день Apia.
- Self-care сохраняет рассчитанный JS `dueAt` одним batch insert.
  Удалены повторные вызовы `make_timestamptz`. Явное назначение даты использует
  тот же helper; правило timezone → client timezone → UTC сохранено.
- Это унифицирует пограничные DST-случаи self-care с общим контрактом:
  например, Amsterdam 29.03.2026 02:30 становится 01:00Z,
  а 25.10.2026 02:30 — 00:30Z. Ранее финальная SQL-конверсия имела другие
  правила разрешения неоднозначности. Существующие сохранённые даты не мигрируются.

Основные файлы: `packages/contracts/src/time/time.service.ts`,
`apps/api/src/modules/self-care/self-care.repository.postgres.ts`.

### TD-03 и TD-04. Кэш страниц и команды по id

- Cursor и infinite-cursor keys находятся под ключом задач текущих workspace
  и auth session. Cancel/invalidate теперь охватывают все соответствующие страницы.
- Общий cache helper обновляет загруженные записи при optimistic write,
  подтверждении сервером, drain офлайн-очереди и откате. Он сохраняет состав
  и порядок каждой страницы до повторного запроса.
- Страницы наблюдают за snapshot; старая версия из cursor не перекрывает
  более новую snapshot-запись. Уведомления подписки проходят через
  `notifyManager.batchCalls`, как в React Query, чтобы не обновлять React во время render.
- Поиск для команд учитывает snapshot и все загруженные страницы текущей
  сессии, выбирает максимальную версию и включает запись в snapshot перед
  командой. Expected version и сохранение в IndexedDB доступны и для ранее
  отсутствовавшей записи. Ограничения основного read model не увеличены.
- Интеграционные тесты запускают настоящие hooks и QueryClient с fake IndexedDB:
  edit online/queued, offline + reconnect, rollback, delete, status с поздней
  страницы истории, stale response, server events, изоляция сессий и hydration.

Основные файлы: `planner-task-cache.ts`, `usePlannerTaskCursor.ts`,
`usePlannerState.ts`, `planner-mutations.ts`, `planner-offline.ts` в web planner feature.

Чтобы уложиться в существующий бюджет initial JS, уведомление о действиях с задачей
выделено в `PlannerTaskActionSnackbar.tsx`. Модуль прогревается после авторизации;
при ошибке загрузки сохранённое действие не теряется, остаются сообщение и кнопка
закрытия, а основной planner продолжает работать. Проверены кнопки цепочки,
swipe и отказ загрузки дополнительного модуля. Порог bundle budget не повышался.
