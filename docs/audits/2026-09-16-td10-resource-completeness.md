# TD-10: полнота оценки нагрузки

Реализован выбранный пользователем вариант 1 из [предыдущего отчёта](2026-09-16-selected-fixes.md). Остальные варианты не внедрялись. Production и реальные пользовательские данные не изменялись.

## Поведение

- Счётчик **«Оценено X из Y»** виден и в свёрнутом антиперегрузе.
- 12 неоценённых задач показывают **«Оценено 0 из 12»**, **«неполная оценка»**, а после раскрытия — **«Нагрузка пока неизвестна»**. Нулевой расход за них не показывается.
- `null` означает отсутствие оценки. Явно выбранный `0` — нейтральная задача с известной оценкой. В создании и редактировании есть отдельные варианты **«Не указано»** и **«Нейтрально»**; оценка необязательна.
- При смешанном наборе видны оценённая часть и количество задач без оценки. Если известная часть выше лимита, это подписано именно как результат по оценённой части: неизвестные задачи могут как расходовать, так и восстанавливать ресурс.
- Только полностью оценённый набор из полной доступной выборки получает обычный индикатор «спокойно / на грани / перегруз». Подтверждённо пустой набор показывает «нет задач»; ошибка загрузки пустым планом не считается.
- Ошибка чтения задач, offline, восстановление сессии, загрузка кеша или неполная выборка исключают уверенный итоговый вывод. Счётчик при этом относится к загруженным задачам.
- Состав расчёта сохранён: задачи с планом на сегодня и выполненные сегодня. Просроченные задачи без плана на сегодня и отдельные разделы заботы, уборки и покупок не добавлялись. Состав явно указан в раскрытом блоке.

Полнота данных проверяется по выборкам активных и закрытых задач. Одна полная выборка календарного диапазона недостаточна: выполненная сегодня задача со старой датой планирования может находиться за курсором истории. При неполной истории индикатор остаётся осторожным. Состояние относится к последней загруженной выборке и не является гарантией мгновенной синхронизации со всеми устройствами.

## Совместимость старых нулей

До изменения пустой UI picker сохранял `0`; отдельного выбора нейтрального значения не было. Поэтому простая проверка `resource !== null` сохранила бы исходный дефект для ранее созданных задач.

Миграция `db/migrations/20260916_000105_task_resource_unknown.sql` переводит существующие нули в `null`. Это консервативная трактовка: отличить старый пустой выбор от нуля, переданного напрямую через API, невозможно. Старый явно заданный API-ноль после миграции также потребует повторного выбора «Нейтрально». Ненулевые значения и существующие `null` не меняются.

Обычное увеличение версии записи сохранено: устаревшее офлайн-изменение встретит конфликт вместо незаметной перезаписи. Миграция не создаёт событий задач, поэтому после релиза нужен новый snapshot — обновление приложения/данных. Оценки, созданные новым интерфейсом после миграции, сохраняют различие `null` и `0`.

Старые резервные копии, старые клиенты и старые команды, которые ещё передают пустую оценку нулём, могут вернуть неоднозначные значения. Формат backup и API не менялся; при восстановлении таких данных нулевые оценки нужно перепроверить. Применять миграцию повторно после появления новых явных нейтральных оценок нельзя.
