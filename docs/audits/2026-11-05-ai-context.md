# Аудит AI-контекста — 2026-11-05

Проверены локальные исходники `ai-context` и `mcp-haotika`, контракты задач,
уборки, покупок и заботы. Проверки используют синтетические данные.
Это не аудит актуальных персональных данных и не подтверждение развёртывания
исправлений на production.

## Исправления

1. **Разрешения разделов.** `include: []` раньше требовал ноль scopes, но сервис
   возвращал все разделы. Пустой и отсутствующий список теперь имеют общую
   семантику и требуют полный набор scopes. Регрессия проверяет отказ для
   действующего токена с правами только на задачи.
2. **Посторонние данные в ответе.** Запрос задач мог раскрывать уборку и заботу
   через общие списки просрочки и гибких целей. Детали и coverage теперь
   соответствуют выбранным разделам. `stats` возвращает агрегаты без названий
   посторонних дел. Ненужные источники для узкого запроса не загружаются.
3. **Прогресс задач.** При наличии `completedAt` выполнение учитывается по его
   локальной дате, а не по дате плана или UTC-дню. Архив больше не считается
   выполнением. Для старых записей без `completedAt` сохранён fallback на дату
   плана/срока.
4. **Нагрузка и ресурс.** Одна задача, одновременно запланированная сегодня и
   просроченная по сроку, не удваивает активный счётчик. Независимые одноимённые
   задачи считаются отдельно. Отбор `lowEnergy` учитывает знак ресурса:
   большой расход исключён, восстановление включено, неизвестный ресурс не
   подменяется нулём. Недельный контекст учитывает как дату плана, так и срок;
   календарный блок считается только по плану. Сокращение списков задач
   привязано к дате запроса, а не текущей системной дате.
5. **Уборка.** Включены общие задачи (`generalItems`), убрано молчаливое
   ограничение первыми 14 днями. Одноимённые задачи разных зон не сливаются.
6. **Поиск и покупки.** Фильтр `todo` охватывает активные статусы разных доменов.
   Просроченная забота не дублируется как запланированная. Даты ограничивают
   поиск покупок; недельный прогресс покупок исключает выполнения вне периода.
7. **Входные данные.** Несуществующие даты, неизвестные часовые пояса,
   перевёрнутые диапазоны и периоды длиннее 31 дня дают понятную ошибку.
   Поиск принимает явный часовой пояс. Для длинного обзора нужны несколько
   запросов.

Исправления гибких задач и кнопка снятия даты из предыдущего этапа сохранены.

## Продолжение аудита: оставшиеся пункты исправлены

- Поиск задач выполняется в memory/PostgreSQL до ограничения страницы; учитывает
  текст, статус, дату плана/срока/выполнения и владельца. Для task-only запросов
  доступны nextCursor и точное количество совпадений. Смешанный поиск сообщает
  усечение; полное чтение задач выполняется отдельным task-only запросом.
- Дневной/недельный прогресс берётся из отдельной выборки по completedAt,
  с точным счётчиком и страницей из 50 записей. Дальнейшие страницы можно читать
  через search_planner. Указатели страниц не обрезаются как длинный пользовательский
  текст и не выдаются при одном лишь stats.read.
- История и аналитика заботы фильтруются по локальным суткам в обоих хранилищах.
  Исправлены границы месяца, 23/25-часовые дни DST, локальный прогресс гибких целей,
  завершение одноразовых целей и повторы от даты выполнения. PostgreSQL загружает
  полный период гибкой цели даже для более короткого аналитического запроса.
- AI-день и период показывают фактическую локальную дату выполнения заботы,
  отдельно сохраняя исходную дату расписания.
- Гибкие цели идентифицируются по исходной записи и периоду: одноимённые цели
  остаются отдельными, переименование не меняет идентичность.
- Выбор разделов недели реализован вместе со схемой, scopes и выборочной загрузкой.
  Невыбранные данные не выдаются; stats содержит только агрегаты.
- Даты плана, дедлайна и завершения задач разделены в ответе. Календарь имеет
  собственную выборку и coverage; общий счётчик дел не дублирует задачу из-за
  наличия времени. Вес временного блока в оценке нагрузки сохранён.
- listCoverage описывает каждый сокращённый список ответа, sourceCoverage —
  полноту чтения хранилища. Списки сокращаются один раз в конце формирования
  ответа, с опорой на дату запроса.

## Практические ограничения

Обзор активных задач и покупок по-прежнему ограничивает объём чтения, а итоговые
списки ограничены 50 элементами. Эти ограничения явно отражаются в coverage.
Поиск задач и история выполнений имеют постраничное чтение; поиск покупок
остаётся поиском в ограниченной выборке. Запрос периода ограничен 31 днём.
Пагинация не является транзакционным снимком: параллельные изменения данных могут
изменить состав и счётчики последующих страниц.

На момент завершения аудита изменения проверялись локально. Они включены
в состав [релиза 1.1.32](../release-notes.md#v1132---2026-11-05);
результаты проверок ниже относятся к аудиту до выпуска.

## Проверки

Регрессии включают более 1100 активных задач, поиск за пределами старой выборки,
310 выполнений с полным обходом страниц, права выбранных разделов, идентичность
целей, локальные сутки и DST. Проверки PostgreSQL используют отдельные тестовые
аккаунты и удаляют их после выполнения. Прошли 442 API-теста, 34 проверки
репозиториев на PostgreSQL, lint и typecheck проекта. После итогового review
добавлена регрессия сохранения веса календаря в оценке нагрузки; все 32 теста
AI-сервиса прошли повторно. UI снятия даты проверен на предыдущем этапе.
